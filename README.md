# tcp_scaner

Требуется Go 1.25.5; используются только пакеты стандартной библиотеки.

## Текущий этап

Реализован только внутренний пакет `internal/tcpcheck`, не публичный сканер.
Он не содержит пула, каналов результатов или проверки/нормализации целей.

`tcpcheck.Check(ctx, host, port, timeout) tcpcheck.Result` выполняет одну
TCP Connect-проверку. Вызывающий код передаёт проверенный хост без порта
(IPv6 — без скобок), порт 1–65535 и строго положительный таймаут.

Результат содержит исходный `Host`, `Port`, фактический `IP`, `State`,
`Duration` и исходную `Err`. Состояния: `Open`, `Closed`, `Timeout`,
`Unreachable`, `Canceled`, `Error` со строковыми значениями из ADR.
Успешное соединение сразу закрывается; ошибка закрытия не меняет `Open`.
Длительность включает весь вызов подключения, включая DNS, но не закрытие.

DNS и выбор адреса/fallback выполняет стандартный `net.Dialer.DialContext`.
IP берётся только из удалённого адреса успешного TCP-соединения; при ошибке
отсутствует. Отмена или дедлайн внешнего контекста при неуспешной проверке
дают `Canceled`, собственный таймаут подключения — `Timeout`.

## Проверки

```sh
gofmt -w internal/tcpcheck
go vet ./...
go test -race ./...
```

Тесты проверяют только экспортируемый API из внешнего тестового пакета:
локальное соединение, его закрытие, IP, длительность, отмену и дедлайн
внешнего контекста. IPv6-тест пропускается, если loopback недоступен.
Внешние сети и подмена внутренних зависимостей не используются.
Системные ошибки, DNS-ошибки и собственный таймаут не покрыты отдельными
детерминированными сценариями: текущий API не позволяет воспроизвести их
без зависимости от окружения или вмешательства во внутреннюю реализацию.
