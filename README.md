# tcp_scaner

Компактный встраиваемый TCP Connect-сканер. Требуется Go 1.25.5;
только стандартная библиотека, без CLI, HTTP, SYN/UDP и определения сервисов.

## Использование

```go
package main

import (
	"context"
	"fmt"
	"log"
	"time"

	portscan "github.com/asvec6767/tcp_scaner"
)

func main() {
	scanner, err := portscan.New(portscan.Config{
		Concurrency:    32,
		ConnectTimeout: 500 * time.Millisecond,
	})
	if err != nil {
		log.Fatal(err)
	}
	common, err := portscan.Ports(22, 80, 443)
	if err != nil {
		log.Fatal(err)
	}
	extra, err := portscan.Range(8000, 8002)
	if err != nil {
		log.Fatal(err)
	}
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel() // обязательно и при досрочном прекращении чтения
	results, err := scanner.Scan(ctx, []string{"127.0.0.1", "::1"}, portscan.Merge(common, extra))
	if err != nil {
		log.Fatal(err)
	}
	for result := range results {
		fmt.Printf("host=%q ip=%v port=%d state=%s duration=%s err=%v\n",
			result.Host, result.IP, result.Port, result.State, result.Duration, result.Err)
	}
}
```

## Публичный API

- [`New(Config)`](portscan.go:51) создаёт неизменяемый сканер. Оба поля конфигурации —
  лимит одновременных проверок и таймаут подключения — строго положительные.
  Неявных значений по умолчанию нет; нулевой сканер использовать нельзя.
- [`Scanner.Scan`](portscan.go:66) принимает контекст, список хостов и набор портов,
  возвращает канал результатов и синхронную ошибку валидации. Весь ввод проверяется
  до запуска горутин. Пустые списки, некорректные хосты, отсутствующий или уже
  отменённый контекст запрещены. Ошибку контекста можно проверять стандартным
  сопоставлением ошибок.
- [`Result` и `State`](portscan.go:20): исходный хост, фактический IP, порт,
  состояние, длительность и исходная ошибка. Состояния: open, closed, timeout,
  unreachable, canceled, error. Длительность включает DNS и подключение.
  Ошибки DNS/соединений приходят в результатах, а не вторым возвратом сканирования.
- [`Ports`, `Range`, `Merge`](portscan.go:96) создают и объединяют
  неизменяемые наборы. Границы 1–65535, диапазоны включительные; неверное значение
  или обратный диапазон — ошибка без частичного набора. Дубликаты удаляются с
  сохранением порядка первого появления. Нулевой набор, пустой список и пустое
  объединение допустимы как значения, но запрещены при сканировании.
  [`PortSet.Values`](portscan.go:140) возвращает независимую копию для чтения/изменения.

Один публичный пакет находится в корне модуля. Наборы портов входят в тот же
API: отдельного публичного пакета портов нет. Это библиотека без исполняемой
команды, поэтому каталог команд не создаётся.

Весь публичный API — типы, константы, функции и методы — собран в
[`portscan.go`](portscan.go). Внутреннее выполнение пула находится в
[`scanner.go`](scanner.go); интерфейсы зависимостей — в [`deps.go`](deps.go),
конкретные адаптеры — в [`adapters.go`](adapters.go).

## Лимит, память и отмена

Лимит действует **на один вызов**: параллельные вызовы одного сканера имеют
независимые пулы. Экземпляр безопасен для повторного и конкурентного использования.
Входы копируются до возврата из вызова; дальнейшее изменение исходного списка
не влияет на сканирование. Как обычно в Go, изменять список одновременно с самим
вызовом нельзя.

Хосты × порты перебираются лениво. Полная матрица не создаётся; нет отдельной
горутины на пару. Очередь заданий и буфер результатов ограничены размером пула.
Память — O(хосты + порты + конкурентность), а не O(хосты × порты).
Медленный читатель создаёт обратное давление.

Без отмены приходит ровно один результат на уникальную нормализованную пару,
порядок не гарантируется. При отмене прекращаются новые проверки, активным
подключениям передаётся отмена, ожидания очередей/отправок разблокируются.
Единственный владелец закрывает канал после завершения всех работников.
После отмены поток может быть неполным: результаты отменённых проверок не
гарантируются, синтетических результатов для оставшихся заданий нет.
**Если потребитель перестал читать, он обязан отменить контекст.**

## Хосты и одиночная проверка

Нормализация удаляет внешние пробелы, канонизирует IP, приводит DNS к нижнему
регистру и удаляет конечную точку. Дубликаты удаляются по нормализованному адресу.
При этом результат сохраняет точную исходную строку **первого** появления,
включая пробелы. Для подключения используется отдельно нормализованный адрес.

Поддерживаются IPv4, IPv6 без скобок и ASCII DNS (однометочные и готовые punycode
имена включительно). IPv4-mapped IPv6 дедуплицируется с IPv4. URL, порт в хосте,
CIDR, IPv6 zone, Unicode и подчёркивания запрещены. DNS-метки: 1–63 байта,
буквы/цифры/дефис без дефисов по краям, полное имя — до 253 байт без конечной
точки. Чисто числовые строки с точками или без них должны быть строгим IPv4.
Проверяется синтаксис, не существование имени.

DNS, выбор адреса и fallback выполняет стандартный сетевой dialer без отдельного
кеша и без сканирования каждого IP имени. Успешное соединение сразу закрывается.
IP берётся только из удалённого адреса успешного соединения; при ошибке может
отсутствовать. Отмена/дедлайн внешнего контекста — canceled, собственный таймаут
подключения — timeout. Классификация и исходные ошибки принадлежат внутренней
одиночной проверке, сканер их не переопределяет.

## Зависимости и проверки

Узкие интерфейсы нормализатора и проверки объявлены на стороне потребителя в
[`deps.go`](deps.go): только интерфейсы, использующие типы потребителя.
Они описывают зависимости текущего пакета от других пакетов проекта, не являются
публичным API и не экспортируют внутренние интерфейсы наружу.
Конкретные структуры-адаптеры в [`adapters.go`](adapters.go) связывают их с существующими
функциями внутренних пакетов и преобразуют данные; конструктор подключает
конкретные реализации. Основной код в [`scanner.go`](scanner.go) не импортирует
внутренние пакеты. Публичные результат и состояние в [`portscan.go`](portscan.go)
самостоятельны, но значения состояний связаны с константами внутренней проверки,
а не заданы повторно. Публичной DI-конфигурации,
изменяемых глобальных зависимостей и общего пакета моделей нет. Набор портов —
входное значение, а не сервис: лишнего интерфейса для него нет.
Функциональные подмены используются только в тестах, не в производственных адаптерах.

```sh
gofmt -w .
go vet ./...
go test -race ./...
go test -race -count=20 ./...
git diff --check
```

Тесты корневого пула используют детерминированные подмены через внутренние
интерфейсы и синхронизацию каналами, без задержек для синхронизации и внешних
сетей. Интеграция проверяется локальным TCP-listener через экспортируемый API.
Обёрнутые DNS/системные ошибки и окно истечения внешнего дедлайна проверяются
отдельными внутренними тестами классификатора; реальные сетевые таймауты и
DNS с несколькими адресами не воспроизводятся искусственно на реальной сети.
Преобразование всех состояний, сохранение исходных ошибок и независимость IP
проверяются непосредственно на границе адаптера. Тесты самого пула используют
только типы потребителя.
