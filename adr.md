# ADR: компактный пакет TCP-сканирования

## 1. Границы проекта
- Go 1.25.5, только стандартная библиотека; разделение на небольшие функциональные пакеты.
- Только TCP Connect: без CLI, HTTP, БД, CIDR, SYN/UDP и определения сервисов.
- Без слоёв repository/service, публичных интерфейсов «на будущее» и лишних настроек.

## 2. Публичный API
- `New(Config) (*Scanner, error)`; в `Config` только `Concurrency` и `ConnectTimeout`. Оба значения строго положительные; неявных значений по умолчанию нет.
- Публичный пакет `ports`: `Ports(numbers ...int) (PortSet, error)` и `Range(from, to int) (PortSet, error)` создают наборы; `Merge(sets ...PortSet) PortSet` объединяет их. Внутреннее представление закрыто.
- `Scan(ctx context.Context, hosts []string, ports ports.PortSet) (<-chan Result, error)` запускает поток результатов. Порядок результатов не гарантируется.
- `Result`: исходный `Host`, фактический `IP` (`net.IP`), `Port`, `State`, `Duration`, `Err`.
- `State`: `open`, `closed`, `timeout`, `unreachable`, `canceled`, `error`; состояния экспортируются как константы.
- Ошибка возврата `Scan` — неверный ввод или уже отменённый контекст; ошибки DNS и подключений — в результатах. Продолжительность включает разрешение DNS и подключение.

## 3. Правила входных данных и DNS
- Пустые списки хостов/портов, пустой хост, хост с портом, некорректный IP/DNS — ошибка до запуска горутин.
- Поддержать IPv4, IPv6 без скобок и обычные DNS-имена; не принимать URL. Проверку формата отделить от разрешения DNS.
- Порты только 1–65535; отрицательные значения, 0 и обратные диапазоны запрещены.
- Дубликаты портов удалять; хосты очищать от внешних пробелов, IP нормализовать, DNS приводить к нижнему регистру и убирать конечную точку; затем удалять дубликаты.
- DNS поручить `net.Dialer.DialContext`: для нескольких адресов использовать его стандартный выбор и fallback, а не сканировать каждый IP отдельно.
- У открытого порта IP брать из удалённого адреса соединения. При неуспехе IP может отсутствовать; не угадывать его по тексту ошибки.
- Неразрешимое DNS-имя даёт `error` для каждого его порта. Отдельный DNS-кеш не нужен.
- `targets.Normalize([]string) ([]Target, error)` синхронно проверяет весь список; при ошибке возвращает `nil` и ошибку с индексом и исходной целью. `Target.Host` сохраняет исходную строку первого появления, включая внешние пробелы; `Target.Address` содержит нормализованный хост подключения и служит ключом дедупликации. Порядок первого появления сохраняется. Корневой сканер передаст `Address` в `tcpcheck.Check`, а публичный `Result.Host` заполнит из `Target.Host`; контракт `tcpcheck` не меняется.
- IPv4-mapped IPv6 приводится к IPv4; IPv6 zone и скобки запрещены. Строки только из цифр и точек допускаются лишь как строгий IPv4 (без ведущих нулей, сокращений и конечной точки), а не как DNS.
- DNS: ASCII-буквы, цифры и дефисы внутри непустых меток; дефис не может быть первым/последним. Метка — 1–63 байта, полное имя без единственной необязательной конечной точки — 1–253 байта. Однометочные имена и готовые punycode-имена допустимы; Unicode/IDNA-преобразование, подчёркивания и пустые метки не поддерживаются. Проверяется синтаксис, не существование имени.

## 4. Выполнение и отмена
- Конфигурация сканера неизменяема; каждый вызов создаёт собственные каналы и группу работников. Экземпляр допускает повторные и параллельные вызовы.
- Один ленивый производитель перебирает хосты × порты; очередь ограничена, вся матрица заданий в памяти не создаётся.
- Фиксированный пул работников использует `net.Dialer` с таймаутом и контекстом. Лимит действует на один вызов `Scan`; параллельные вызовы имеют независимые лимиты.
- Каждое успешное соединение сразу закрывается. Измерение времени — отдельно на задание.
- Канал результатов имеет небольшой буфер размером с пул. Медленный читатель создаёт обратное давление, а не неограниченный рост памяти.
- При отмене прекратить выдачу новых заданий и отменить активные подключения. Ожидание задания и отправка результата также учитывают контекст.
- `canceled` означает отмену контекстом вызывающего кода; истечение собственного таймаута подключения означает `timeout`.
- Без отмены возвращается один результат на каждую уникальную пару хост/порт. После отмены допускается неполный поток, включая пропуск результатов активных операций; синтетические результаты для всей оставшейся очереди не создаются.
- Канал закрывает единственная служебная горутина после завершения работников. Если читатель прекращает чтение раньше времени, он обязан отменить контекст.

## 5. Классификация ошибок
- Использовать `errors.Is` / `errors.As`, `context`, `net.Error`, `net.DNSError` и системные коды; текст ошибок не сравнивать.
- Приоритет: отмена/дедлайн внешнего контекста → `canceled`; ошибка DNS → `error` (таймаут DNS → `timeout`); таймаут подключения → `timeout`; отказ соединения → `closed`; недоступность сети/хоста → `unreachable`; остальное → `error`.
- Исходную ошибку сохранять в `Err`; у `open` ошибки нет. Различия системных кодов изолировать в маленьких платформенных файлах только при необходимости.

## 6. Минимальная структура
- `go.mod` — модуль и версия Go.
- Корневой публичный пакет `portscan` — конфигурация, результаты, конструктор, пул, отмена и поток результатов.
- Публичный пакет `ports/` — наборы портов, диапазоны, объединение и валидация.
- `internal/targets/` — проверка и нормализация хостов, удаление дубликатов; без DNS-запросов.
- `internal/tcpcheck/` — одиночное подключение, закрытие соединения, IP, длительность и классификация ошибок.
- Только `portscan` зависит от остальных пакетов; они не зависят друг от друга и от корневого. Внутренний результат проверки преобразуется в публичный в `portscan`; общий пакет моделей не нужен.
- При реальной зависимости от другого пакета проекта узкий интерфейс объявляется на стороне потребителя в `deps.go`. Без такой необходимости не создавать интерфейсы, `deps.go` или обёртки стандартной библиотеки; `targets` и `tcpcheck` остаются независимыми.
- Тесты рядом с кодом; отдельных пакетов для пула, конфигурации и утилит не создавать.
- Тестировать только наблюдаемое поведение через экспортируемый API каждого пакета, включая внутренние пакеты проекта. Тесты писать во внешнем пакете `<имя>_test`: не обращаться к неэкспортируемым функциям, не подменять внутренние зависимости и не фиксировать детали реализации. Не расширять API ради тестов. Изменение внутренней реализации при сохранении контракта не должно требовать изменения тестов.
- `README.md` — пример использования, API, правила DNS, лимиты, отмена и команды проверки.

## 7. Порядок реализации и приёмка
1. Создать модуль, типы и зафиксировать контракты API из этого документа.
2. Реализовать наборы портов и валидацию целей; покрыть границы, дубликаты и ошибочный ввод табличными тестами.
3. Реализовать одиночную проверку и классификатор; проверять доступные через экспортируемый API сценарии без внешних сетей и привязки к внутреннему классификатору.
4. Добавить пул, ограниченные каналы, отмену и гарантированное закрытие соединений/канала.
5. Проверить открытый порт, фактический IP и закрытие соединения локальным TCP-listener; отмену и дедлайн внешнего контекста — через экспортируемый API. Не использовать внешние сети, нестабильный DNS или предположения о доступности случайного порта. Если недоступность, собственный таймаут или DNS-ошибку нельзя детерминированно воспроизвести через текущий API, явно отметить ограничение покрытия, а не вводить тестовые точки расширения или обращаться к внутренностям.
6. Проверить предел одновременных проверок, медленного читателя, прекращение чтения с отменой, повторные/параллельные вызовы и завершение работников. IPv6-тест пропускать, если loopback недоступен.
7. Написать короткий README с рабочим примером, выполнить `gofmt`, `go vet ./...` и `go test -race ./...`.

Критерий готовности: небольшой встраиваемый пакет, предсказуемые ошибки, ограниченная конкурентность и память, отсутствие гонок и зависших горутин при соблюдении контракта чтения/отмены.
